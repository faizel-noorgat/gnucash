## Done

- **2026-09-19** — *Closed the tenant isolation surface (B-0005).* RLS had policed only the 36 tables carrying a direct `tenant_id`; **14 tables reached a tenant only through a parent FK and had no policy**, so raw SQL over `accounting_journalline` returned every tenant's ledger lines. Five payload-carrying children got an explicit `tenant_id`, populated from the parent by `TenantDerivedChildModel` and kept in agreement by a **composite foreign key** `(parent_id, tenant_id) → parent(guid, tenant_id)` — chosen over a trigger, which could only have enforced it by silently rewriting a wrong value. Nine relationship/sidecar tables got **`EXISTS` policies with matching `WITH CHECK`**. Policies moved from `TO PUBLIC` to **`TO app_user`**; the `tenants` registry itself is now policed on its own primary key, with a narrow INSERT carve-out so registration can create a tenant before any membership exists. Four permissive `SELECT` policies grant a caller their own memberships, grants, engagements and tenants, because `can_access_tenant()` reads the very tables RLS confines and would otherwise answer `False` for everyone. 51 of 65 tables under FORCE RLS, 57 policies, one principal. RLS tests **26 → 74**; suite **217 → 265** collected. Verified from an empty database.
- **2026-09-19** — *Three defects found while closing the isolation surface, none of them in the brief.* **`TenantContextMiddleware` had never had any effect**: it set context in `MiddlewareMixin.process_request`, which runs in autocommit, so every `SET LOCAL` was discarded before the view ran — confirmed directly against PostgreSQL (`WARNING: SET LOCAL can only be used in transaction blocks`). It is now new-style middleware owning a `transaction.atomic()` around `get_response`. **`X-Tenant-ID` was trusted from the client with no authorization check**, so any caller — including an unauthenticated one — could assume any tenant and RLS would dutifully confine them to it; the requested tenant is now put to `AuthorizationService.can_access_tenant()` before any context is established, and a refusal leaves none behind. And the **first draft of `rls/0004` created policies on 14 tables without enabling RLS** — PostgreSQL does not evaluate a policy unless `relrowsecurity` is set, so those tables were wide open while `pg_policies` listed them.
