## Done

- **2026-09-19** — *Posting became one atomic domain operation.* `DocumentPostingService.post_document()` now locks the document (`select_for_update`), re-validates against the locked row rather than the caller's stale instance, posts the journal entry, marks the document posted and writes the `DOCUMENT_POSTED` audit event inside a single `transaction.atomic` block, then refreshes the caller's instance. This deliberately replaces the legacy two-step caller contract, which left a window in which a posted `JournalEntry` could coexist with a document still reading DRAFT. The test's manual `mark_posted()` call was removed and its assertions extended to cover the repeated-post case by journal *count*, not merely by exception. (Resolves Q-0003.)
- **2026-09-19** — *Implemented the three stub identity services against their contract tests.* `AuthenticationService` (`authenticate_user`, `generate_access_token`, `validate_token`, `enroll_mfa`), `AuthorizationService` (`is_tenant_member`, `get_accessible_tenants`, `has_permission`, `can_access_tenant`) and `TenantService` (`create_tenant`, `get_tenant`) — all class-level, because that is how the tests call them. Tokens are `django.core.signing` under a dedicated salt with every failure mode collapsing to `None`; `authenticate_user` hashes even on the no-such-user path so login is not a user-enumeration oracle; `can_access_tenant` requires direct membership or the full advisor chain (practice membership, active engagement, active grant).
